## 二、从像素到 patch：先追踪形状

普通文本 LLM 的输入接口接收 token ID，再查表得到向量；原始 RGB 像素不能直接作为这些词表 ID。这里不是说神经网络不能处理像素，而是需要一个**视觉输入路径**，把像素转换成适合后续网络使用的表示。

设一张图高 `H`、宽 `W`、通道数 `C`。本节约定图像形状为 `(H, W, C)`；框架也常使用 `(B, C, H, W)`，其中 `B` 是一批图片的数量。**换轴顺序不等于改变图片内容**，但读形状时必须知道约定。

假设 `H、W` 都能被 patch 边长 `P` 整除，不重叠、不补边：

- patch 数量 `N = (H / P) × (W / P)`。
- 每个 patch 有 `P × P × C` 个数，展平后记为长度 `K = P²C` 的向量。
- 一张图的所有 patch 组成矩阵 `X_patch`，形状是 `(N, K)`。

例如，`224 × 224` 的 RGB 图，`P=16`：有 `14 × 14 = 196` 个 patch，每个 patch 是 `16 × 16 × 3 = 768` 个数，所以形状为 `(196, 768)`。这里的 768 是**像素数乘通道数**，尚未代表模型的隐藏维度。

![像素到 Patch Token 的过程图](../images/ch2-patch-tokenization.svg)

### 手算一个能看见每个数的例子

为方便计算，用 `4 × 4 × 1` 灰度图，按行优先切成四个 `2 × 2` patch：

```text
图像                  展平后的 patch，每行对应一个位置
 1  2 |  3  4         左上：[ 1,  2,  5,  6]
 5  6 |  7  8         右上：[ 3,  4,  7,  8]
------+------         左下：[ 9, 10, 13, 14]
 9 10 | 11 12         右下：[11, 12, 15, 16]
13 14 | 15 16
```

此时 `N=4, K=4`。**切块和展平只是重排数据，还没有学习特征，也没有识别出任何物体。** 若实际尺寸不能整除，必须看具体 processor 的缩放、裁剪或补边策略，不能直接套用整数公式。

## 三、从 patch 到 ViT 特征：投影、位置与信息交换

### 3.1 线性投影改变“每个位置有几个数”

让每个 patch 乘同一个可训练矩阵 `E`，形状为 `(K, D_v)`，可再加偏置。于是：

```text
X_patch (N, K) @ E (K, D_v) → patch embeddings (N, D_v)
```

`D_v` 是视觉网络的隐藏维度，由模型设计决定；它可以等于 `K`，也可以不等于。投影不是把向量翻译成词语，更不是给 patch 分配词表 ID。

给上面的灰度例子选一个**人工矩阵**，忽略偏置：

```text
E = [[1, 0],
     [0, 1],
     [1, 0],
     [0, 1]]               # (4, 2)

[1, 2, 5, 6] @ E = [1+5, 2+6] = [6, 8]
全部结果 = [[6,8], [10,12], [22,24], [26,28]]   # (4, 2)
```

这是形状和矩阵乘法练习；真实模型会通过训练更新 `E`，不会固定使用这里的“左右列求和”。官方实现也可以用步长等于 patch 大小的卷积完成这种投影，不一定先显式生成展平矩阵。

### 3.2 ViT 为什么还需要位置和注意力

按 [ViT 原论文 §3.1](https://arxiv.org/html/2010.11929v2#S3.SS1) 的经典设置，在 patch 序列前加一个可学习的 class token，再加位置向量。class token 是一个用于汇总信息的向量位置，不是“猫”这类标签。位置向量告诉网络哪个位置在哪里；它不会增加 token 数或隐藏维度。

```text
patch embeddings            (B, N, D_v)
加 class token、位置向量    (B, N+1, D_v)
多层 Transformer 后         (B, N+1, D_v)
```

注意力让一个位置可以组合其他位置的信息，逐位置的 MLP 再加工表示。因此，最后的某个 patch 特征虽然仍对应原来的位置，内容却可能包含整图上下文，不应理解成只看那一小块像素。注意力如何计算可衔接 [LLM 基础速通](../llm-基础速通.md)。

### 3.3 必须分清两种输出

- **patch 特征序列**：例如去掉 class token 后得到 `(B, N, D_v)`，保留多个位置的表示。
- **整图向量**：选取汇总后的 class 位置，再按任务需要投影，得到 `(B, D_e)`，每张图只有一个向量。

在 [OpenAI CLIP 官方代码 `VisionTransformer.forward`](https://github.com/openai/CLIP/blob/main/clip/model.py) 中，ViT 最后取第 0 个位置、做归一化层和投影，返回整图向量；`encode_image()` 的常规返回值**不是全部 patch 特征**。后续 VLM 若要用 patch 特征，需要从所选视觉层读取相应序列。CLIP 也有 ResNet 视觉分支；本章只沿 ViT 路线展开。

**停下来算一算**：`B=2, H=W=224, C=3, P=16, D_v=768`，加入 class token 后形状是多少？答案是 `(2, 197, 768)`，不是 `(2, 196, 768)`；两个 768 恰好相等，来源却不同。

## 四、分辨率为什么同时影响细节与成本

固定 `P=14` 时，`224 × 224` 有 256 个 patch，`448 × 448` 有 1024 个。边长变成两倍，patch 数变成四倍。若使用标准全局自注意力，单个注意力头的两两得分矩阵约从 `N × N` 增加为 `4N × 4N`，元素数约变成 16 倍。**这不是整个模型延迟或显存必然增长 16 倍**：投影、MLP、内存访问、注意力实现都会影响实测结果。

图像先被缩小后，小字可能已经失去区分笔画所需的信息；再切成更多 patch 也不能恢复丢失的像素。反过来，提高输入分辨率也不保证答对：模型还可能受训练数据、位置编码、连接模块或任务能力限制。

- **Patch**：视觉编码器内部的小块，例如 `14 × 14` 像素。
- **Tile**：先把大图裁成几个较大的子图，再对每张子图做 patch 编码。它能保留局部细节，但会增加输入量，也可能切断跨块关系。

因此应先遵守模型 processor 的尺寸要求，而不是把 `448 × 448` 当成通用起点。具体预处理与小字评测分别见 [第六章](../chapter6/第六章%20推理部署与%20Serving.md) 和 [第五章](../chapter5/第五章%20评测体系与工程选型.md)。

## 五、CLIP 的双编码器：同维度还不等于已对齐

设图像编码器产生特征 `f_i`，文本编码器产生特征 `g_j`。两边经过各自的投影后，得到同样长度 `D_e` 的向量。训练前，即使维度相同，两个坐标系也未必有可比较的语义；**对齐是由目标函数和配对数据学出来的，不是 reshape 出来的**。

[CLIP 论文 §2.2、Figure 3](https://proceedings.mlr.press/v139/radford21a/radford21a.pdf) 给出其核心：两侧投影、L2 归一化、批内相似度矩阵、双向交叉熵。先把其中两个数学步骤拆开。

### 5.1 L2 归一化与余弦相似度

向量 `x=[x₁,…,x_d]` 的长度为 `||x||₂ = sqrt(x₁²+…+x_d²)`。除以长度得到单位向量 `u=x/||x||₂`。例如 `[3,4]` 的长度是 5，归一化后为 `[0.6,0.8]`；零向量不能这样除。

```text
cosine(x,y) = (x · y) / (||x||₂ ||y||₂)
归一化之后：cosine(x,y) = u · v
```

例如 `[1,0] · [0.6,0.8] = 0.6`。余弦相似度在 `[-1,1]`，比较方向而非原始长度。把 `[3,4]` 放大成 `[30,40]` 不会改变余弦分数。

**为什么需要它？** 不归一化时，点积还能靠增加向量长度变大；归一化后，匹配得分主要比较方向。不过“方向相近”是否对应“语义匹配”，仍取决于训练，不是余弦公式自动保证的。

### 5.2 温度把相似度变成训练 logits

记 `s_ij = u_i · v_j`，logit 定义为 `z_ij = s_ij / τ`，其中温度 `τ > 0`。温度越低，同一组分数的 softmax 通常越尖锐，但正的缩放不会改变它们的排序。

[官方 `CLIP.forward`](https://github.com/openai/CLIP/blob/main/clip/model.py) 对两个编码器的输出进行 L2 归一化，并乘 `exp(logit_scale)`。这相当于使用 `1/τ`，不是再乘一次温度。模型学习这个缩放参数；下面为便于手算，固定 `τ=0.5`。注意单独调用官方 `encode_image()` 或 `encode_text()` 后，不能假定其返回值已经做了这里的 L2 归一化。

## 六、手算一整个训练 batch，而不是一对图文

假设一批有两个真实配对：`(I₁,T₁)` 与 `(I₂,T₂)`。为演示，直接指定归一化后的表示；它们不是某个真实模型对猫狗图片的测量结果：

```text
u₁=[1,0]    v₁=[1,0]
u₂=[0,1]    v₂=[0.6,0.8]

                 文本 T₁   文本 T₂
余弦矩阵 S：图 I₁   1        0.6
            图 I₂   0        0.8

τ=0.5，Z=S/τ：    [[2, 1.2],
                  [0, 1.6]]
```

矩阵行是图片，列是文本。对角线两项是数据提供的正配对；另外两项是本 batch 的负配对。一般 `B` 个配对会产生 `B × B` 个得分，绝不是每对独立算一个“相似度损失”。

### 6.1 图片找文本：按行分类

softmax 把同一行的指数值除以它们的总和：

```text
p(T_j | I_i, 本批候选) = exp(z_ij) / Σ_k exp(z_ik)
```

对图片 `I₁`，正确文本是 `T₁`：

```text
p(T₁ | I₁) = exp(2) / (exp(2)+exp(1.2)) ≈ 0.6900
p(T₂ | I₂) = exp(1.6) / (exp(0)+exp(1.6)) ≈ 0.8320
```

交叉熵取正确配对的负自然对数，再对图片取平均：

```text
L_image = [-ln(0.6900) - ln(0.8320)] / 2 ≈ 0.2775
```

为什么用负对数？正确项分到的概率越接近 1，损失越接近 0；若分到接近 0 的概率，损失就很大。它关心的是正确项相对于**这一行其他项**的优势。

### 6.2 文本找图片：按列分类

这一次固定文本，在图片之间选择。每一列单独归一化，不能复用刚才的行概率：

```text
p(I₁ | T₁) = exp(2) / (exp(2)+exp(0)) ≈ 0.8808
p(I₂ | T₂) = exp(1.6) / (exp(1.2)+exp(1.6)) ≈ 0.5987
L_text = [-ln(0.8808) - ln(0.5987)] / 2 ≈ 0.3200
L = (L_image + L_text) / 2 ≈ 0.2987
```

这就是一个 batch 的双向对比损失。训练通过反向传播更新编码器、投影等可训练参数，使真实配对在行和列的竞争中得分更高。本章脚本只算前向结果，**不实现编码器、反向传播或训练**。

### 6.3 三个反事实帮助你真正理解目标

1. **温度从 0.5 改为 1**：得分差被压小，本例损失升到约 `0.4489`。不是温度越低永远越好：若错误项最高，降低温度会更确信错误项，并加大惩罚。
2. **把两条文本顺序交换，却仍把对角线当标签**：本例损失升到约 `1.4987`。这说明图文配对索引是监督信号，数据对错位就会训练错误关系。
3. **batch 只剩一个配对**：行和列都只有一个候选，softmax 都是 1，损失为 0，即使这对表示完全不相似。没有负候选时，这个批内对比目标无法提供区分信号。

实际数据还可能出现“假负例”：两张图都可以匹配同一句描述，却被批内一对一标签当成互斥项。所以“非对角线就是语义上绝对错误”只是本例的教学假设，不能当成真实数据的事实。

## 八、推理：候选相对分数不等于正确率

训练时标签来自配对数据；推理时给一张图和 `M` 条候选文本，计算 `(1, M)` logits。选择最高分文本就能做候选匹配，也可以在该候选集合上做 softmax。此时不需要知道哪个候选正确。

用本例第一张图的 logits `[2,1.2]`，第一项得到 `0.6900`。现在不改变图片和原来的两条文本，只增加一个与第一项表示相同的候选：

```text
原候选：       [2, 1.2]    → [0.6900, 0.3100]
增加重复候选： [2, 1.2, 2] → [0.4083, 0.1834, 0.4083]
只给一个候选： [2]         → [1.0000]
```

原来的相似度没变，分母却变了。这些数字回答“在给定候选与缩放下，分数怎样分配”，没有验证“这句话客观正确的概率是多少”。即使所有候选都错，softmax 仍会给它们分配总和为 1 的概率。未经专门校准和评估，不能把 `0.9` 当成“90% 正确”，更不能把检索分数当成生成答案的可靠度。

## 九、从检索对齐到生成对齐：还缺哪一步

CLIP 的两个塔给出向量和匹配分数，没有自回归解码器来逐 token 写答案。要做“图中按钮为什么不可点击”这样的生成任务，常见路线是把视觉表示作为语言模型的条件输入：

```text
视觉特征 V： (B, N, D_v)
线性 Connector W： (D_v, D_lm)
V @ W：      (B, N, D_lm)
与文本 embedding 一起送入 LLM → 逐 token 预测回答
```

这里的简单线性层保持 token 数 `N`，改变每个 token 的维度；MLP、查询模块等设计也可能改变处理方式或 token 数。**维度匹配只是能接入的前提，随机初始化的 Connector 不会自动让 LLM 理解图像。** 通常还需要用图像条件下的训练目标学习如何利用这些表示。

例如给定图像 `I`、问题 `q`、参考回答 `y₁…y_T`，生成训练可以最小化：

```text
L_generation = -(1/T) Σ_t log p(y_t | I, q, y_1, …, y_(t-1))
```

它监督的是回答 token；CLIP 对比损失监督的是一个 batch 内“哪张图配哪条文本”。两者不是同一个 softmax，也不要求使用同一个嵌入空间。保留 patch 序列提供了更多局部位置，但**不等于每个 patch 都已有一个词级标注或已精确对齐某个词**。

CLIP 是重要例子，不是所有生成式多模态模型的必经训练步骤。关于连接模块、冻结哪些参数、分阶段训练，请进入 [第三章](../chapter3/第三章%20多模态生成架构.md)，对照 [BLIP-2](https://arxiv.org/abs/2301.12597) 与 [LLaVA](https://arxiv.org/abs/2304.08485) 的不同设计。

## 十、把“没看懂”变成可检验的问题

“换一张图回答不变”只能说明需要排查，不能直接证明“对齐训练失败”。同样现象可能来自图片根本没传入、预处理丢失细节、模型忽略证据，或两个样本本来就应得到同一答案。

建议按以下顺序收集证据：

1. **输入链路**：确认实际发送的图片就是目标图片，文件可读、请求确实包含图片字段。
2. **预处理链路**：查看缩放/裁剪后的图片与尺寸，小字是否还能被人辨认。
3. **协议链路**：核对 `messages.content`、图像字段和 chat template。`400`、`422` 或缺图提示通常应先查请求格式，具体文案因服务实现而异。
4. **模型链路**：用简单、答案明显且图像证据不同的配对测试，确认模型支持 OCR、定位或其他目标任务。
5. **提示链路**：固定明确的问题，要求基于图像证据回答，再比较提示的影响。

做分辨率实验时，固定模型、问题、候选/解码设置，只改变原图与缩放版本；记录漏看、看错、推错，而不只写“效果差”。这能衔接 [第五章评测](../chapter5/第五章%20评测体系与工程选型.md)，但一对样本仍不足以证明普遍规律。

## 十二、结业练习与验收

**必做（约 15 分钟）**：不看参考输出，手算 `S、Z、L_image、L_text`，运行 toy 脚本核对到小数点后四位。然后完成第七节的三处改动，并解释每次结果。提交一张纸或一个文本文件即可，重点是中间步骤而非截图证明“运行成功”。

**进阶（约 30 分钟，有真实 CLIP 环境再做）**：固定一张图片，分别给 2 条和 5 条候选，再加入语义重复项。记录候选、logits、softmax；用分母变化解释为什么同一句话的概率变了。真实模型产生的不同措辞向量未必相同，不能要求它们完全平分。

**挑战（按需）**：对同一张密集截图准备原图、缩放图，固定三个细节问题，记录预处理尺寸和错误类型。不要仅凭一次回答就认定提高分辨率解决了问题。

## 十三、本章小结与原论文阅读路线

本章的因果链是：**像素切块 → 可学习投影 → 带位置的视觉序列 → 全局或局部表示 → 明确的训练目标 → 有边界的推理解释**。不是“有一个向量，就已经看懂图”。

带着具体问题阅读原始资料：

1. **ViT**：Dosovitskiy 等，[An Image is Worth 16x16 Words](https://arxiv.org/abs/2010.11929)（2020 预印本 / ICLR 2021），读 §3.1、Figure 1、式 (1)，对照 `N、P²C、D` 与 class token。
2. **CLIP**：Radford 等，[Learning Transferable Visual Models From Natural Language Supervision](https://proceedings.mlr.press/v139/radford21a.html)（ICML 2021），读 §2.2、Figure 3 的训练目标，再读 §2.3 的编码器选择；不要把推理候选 softmax 当成训练全貌。
3. **实现核对**：[OpenAI CLIP `model.py`](https://github.com/openai/CLIP/blob/main/clip/model.py)，定位 `VisionTransformer.forward`、`encode_image`、`encode_text` 与 `CLIP.forward`，核对全局输出、L2 归一化及 logit scale 分别发生在哪里。
4. **生成架构**：转到第三章的 BLIP-2 与 LLaVA 原论文，追问“哪些 token 进入 LLM，哪些参数被训练，损失监督什么”。
