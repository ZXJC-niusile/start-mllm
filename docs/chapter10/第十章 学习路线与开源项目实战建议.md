# 第十章 学习路线与开源项目实战建议

前九章分别介绍了模型结构、数据、评测、调用与工作流。本章把这些知识用于安排下一轮实践：**选一个方向 → 确定产出 → 安排进度 → 记录结果**。四步共用一份项目记录，不需要再填写多套学习计划。

如果仍不能解释视觉编码器、连接器与语言模型的关系，先按[前言](../前言.md)回到相应基础章节。阅读理解与项目实作是不同阶段；以下流程供准备实践的读者按需使用。

## 一、选一个需要解决的问题

方向应来自具体任务或已经观察到的失败。先写清输入、期望输出和当前困难，再选择本轮重点：

| 方向 | 适合解决的问题 | 本轮重点 |
| --- | --- | --- |
| 场景验证 | 还不知道模型能否完成某类图文任务 | 固定任务范围，整理样本与评分规则，观察错误 |
| 模型对比 | 同一任务已有多个候选模型 | 固定样本和评分方法，记录各模型的配置、结果与限制 |
| 工作流深化 | 单次问答已暴露需要外部信息或校验的失败 | 选择一个有依据的工具或规则，与原流程比较 |

例如票据总金额抽取：尚未检查任务可行性时，先做场景验证；已有两个候选模型时，可做模型对比；若已发现小计被误当总计，再考虑字段位置或金额校验。不要仅因学过 Agent 就给所有任务增加工具步骤。

## 二、确定一份可检查的产出

围绕所选问题留下一个能复查的小项目。以票据任务为例，产出应包括字段约定、样本及参考答案、运行配置、结果和失败案例。界面可以用于观察，不是每个方向都必须新增 Demo。

| 记录 | 需要说明的问题 | 对应章节 |
| --- | --- | --- |
| 任务与输入 | 处理什么图片，哪些情况不在范围内，字段模糊时如何返回 | 第一章、第四章 |
| 数据与评分 | 参考答案从哪里来，怎样判错；若训练或调参，怎样与最终评测隔离 | 第四章、第五章 |
| 模型与配置 | 模型版本、接口、预处理、提示词和生成参数是什么 | 第三章、第六章、第七章 |
| 结果与失败案例 | 能否回到原图、原始回答和对应配置核对 | 第五章、第八章、第九章 |

在运行前写明检查方式。例如总金额任务应区分字段缺失、读错数字、选错金额字段与接口失败；只统计“返回了非空文字”不足以判断任务是否完成。模型是否适合文档或截图，也应由相应样本的结果支持。

## 三、按产出安排进度

先列出阻碍上述产出的知识或环境缺口，再回查对应章节。已经会做的步骤可以跳过，需要等待接口、数据或设备的步骤应单独记录，不把它们误认为学习能力问题。

下面以已有基础、准备做票据场景验证的读者为例，给出约四周的安排。它是可调整的实践节奏，不是从 Python 起步的固定学时要求，也不要求每个方向都完成全部工具链。

| 阶段 | 工作 | 留下的产出 |
| --- | --- | --- |
| 第 1 周 | 明确总金额字段、输入范围与判错规则，核查图片使用权限 | 任务说明、样本与参考答案 |
| 第 2 周 | 按第七章跑通接口，用第五章的方法记录初始结果 | 配置、原始输出与错误分类 |
| 第 3 周 | 从失败中选择一个原因，修改提示词或预处理后比较 | 修改前后的结果及配置差异 |
| 第 4 周 | 用未参与修改决策的保留样本检查效果，整理仍未解决的问题 | 项目记录、失败案例和下一步决定 |

若选择模型对比，第三阶段改为在相同样本与评分规则下比较候选模型；若选择工作流深化，则比较原流程与增加工具或规则后的流程。仍沿用同一份记录，不另起一套计划。需要界面演示时再接第八章，需要服务观测或工具分支时再查第六章、第九章。

## 四、记录结果并决定下一步

项目说明应让另一个读者知道系统收到了什么输入、怎样运行、怎样判断输出。每次修改记录对应配置，保留原始回答与失败原因；没有实测的效果、耗时或显存保持为待验证项，不填写估计值冒充结果。

完成一轮后，对照第二节的检查方式回答：错误是否减少，是否出现新错误，增加了哪些调用或维护成本？若用于调整的样本表现改善，而保留样本没有改善，就不能据此宣称任务能力普遍提高。

据此选择下一步：证据不足时补充样本；主要问题在输入或配置时修正链路；已有稳定结果时再考虑扩大场景或部署。选择应能回到本轮记录中的具体失败，而非继续堆叠功能。

## 五、用同一份记录完成规划自检

原有的方向选择、能力缺口和学习计划可以集中在一份项目记录中，按需要填写：

1. 写明本轮场景、输入与输出，从第一节选择一个方向，并说明依据。
2. 按第二节列出产出与检查方式；将需要补充的能力对应到章节。
3. 参照第三节安排进度；运行后在同一份记录中补充结果、失败与下一步。

在同一份项目记录中持续更新进度、运行结果和下一步安排。

## 六、需要深入时回到原始来源

遇到模型机制或实现细节无法解释的现象，可从[扩展阅读](../扩展阅读.md)查找相应论文或官方文档，并在同一份项目记录中补充：

- 来源标题与链接，以及本次要验证的具体问题。
- 模型、依赖和数据版本，说明是否采用了原文完整设置。
- 实际结果、失败样例和资源开销，并区分原文结论与本次小样本观察。

局部实现检查或小样本比较只能支持对应范围的结论，不自动构成完整论文复现。
