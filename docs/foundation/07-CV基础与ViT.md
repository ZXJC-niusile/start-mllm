# 07 CV 基础与 ViT：从像素到视觉 token

前置：[06 Transformer 基础](./06-Transformer基础.md)。CV 是 computer vision，即计算机视觉。本章从像素与预处理出发，解释 ViT 如何构造并处理视觉 token。

文本有 tokenizer，图像却不是先变成一段自然语言描述再交给模型。视觉编码器直接处理数值图像，形成一组特征；这些特征是否保留文字、位置和细节，会影响后续 MLLM 能回答什么。

## 7.1 像素只是测量值，还不是物体

一张 RGB 彩色图可表示为 `[H,W,3]`：H 是高度、W 是宽度，最后一轴依次记录红绿蓝通道。8 位图像通常用 0～255 表示通道值；灰度图可能只有一个通道，RGBA 图还有透明度通道。读取图片时必须明确颜色模式，不能只看文件扩展名。

像素值依赖光照、压缩、颜色处理和拍摄设备。同一个物体可以对应不同的像素模式；相似的颜色也可能来自不同物体。视觉模型通过局部结构与上下文学习可用于任务的表示，不是给每一种 RGB 三元组分配一个固定语义。

批量接口还会加入 B 轴，常见布局有 `[B,H,W,C]` 和 `[B,C,H,W]`。布局不同需要换轴，不能用 reshape 假装换了通道顺序。数值总数相同，只能说明存储规模相同，不能证明图像含义一致。

## 7.2 预处理决定模型实际上看到了什么

模型输入通常经过颜色转换、缩放、裁剪或补边、浮点转换与归一化。缩放改变像素网格；裁剪直接丢掉一部分画面；补边保留画面比例但增加空区域。把宽图强行拉成正方形还可能改变几何关系，因此这些选择不能被当成无关紧要的准备工作。

常见数值处理是先把像素缩放到某个范围，再逐通道计算 `(x-均值)/标准差`。所用均值、标准差和插值方式应跟 checkpoint 的预处理配置一致，不能因为“大家都这么写”就把另一模型的参数照搬。processor 封装预处理规则，不意味着所有模型的 processor 可互换。

例如一张票据底部才有总金额：中心裁剪若删除了底部，语言模型再强也无法直接读取已经不存在的像素。把小字缩到模糊，也不能靠增加输出长度恢复可靠证据。这是 OCR 和文档任务必须关注分辨率的原因。

## 7.3 卷积提供了什么基本思路

在卷积网络中，一个小的可学习滤波器在图像的不同位置重复使用，对局部区域做加权计算。权重共享使模型能在多个位置寻找类似局部模式；多层叠加逐渐扩大某个特征能依赖的输入区域，称为感受野。

步幅决定滤波器每次移动多少，补边影响边界如何参与计算，池化或带步幅的运算会减少空间尺寸。下采样降低成本，也可能丢失细节。旋转、缩放和位移会改变特征响应，变化程度还受边界处理和后续结构影响。

这里介绍卷积，是为了建立“局部计算、共享参数、逐步汇聚”的概念。ViT 用另一种方式把空间数据送入 Transformer，并不要求先把整张图识别成物体标签。

## 7.4 Patch embedding：把一个图像块变成一个向量

按[原始 ViT](https://arxiv.org/abs/2010.11929)的固定、不重叠切块思路，设 RGB 图像大小为 `224×224`，patch 边长为 16，且尺寸恰好整除：

```text
patch 网格：14 × 14
patch 数 N：196
每个原始 patch 的数值个数：16 × 16 × 3 = 768
展平后：[N,768]
线性投影后：[N,Dv]
```

`Dv` 是视觉隐藏宽度，由模型设计决定，不必等于 768。若 `Dv=512`，投影矩阵按数学约定为 `[768,512]`，输出 `[196,512]`。patch 是原图的一块区域，patch embedding 是该区域的特征向量，二者不能都当成原始像素。

切块与展平没有完成跨块交流；后续 Transformer 才让一个位置读取其他位置的信息。经过多层交互，某个 patch 位置的输出可能包含整张图的上下文，不能再严格解释为只描述原来那一小块。

## 7.5 位置、CLS 和特征读取

只把 patch 看成一组向量，会丢失排列信息。因此需要位置表示帮助区分左上、右下等位置。二维网格如何映射成序列、分辨率变化时如何处理位置表示，是架构的一部分。

原始 ViT 分类设置会加入一个可学习的 class token，通常称为 CLS；在 196 个 patch 之外，序列长度变成 197。模型可用它经过编码后的表示进行分类。其他模型可能采用池化或不同读取方式，所以不能认为所有视觉编码器都输出一个 CLS，也不能认为送入 MLLM 的一定就是这个向量。

全局图像向量适合某些分类和检索任务；保留多个空间位置的特征，则为后续读取细节提供更多入口。读取哪一层、是否去掉 CLS、是否归一化、保留多少位置，都会影响连接器接口。

## 7.6 分辨率增加怎样影响成本

同样采用 16 像素 patch，将边长从 224 改为 448，patch 数变为 `28×28=784`，是原来的 4 倍。固定特征宽度下，patch 特征元素数也约增至 4 倍；只看不含特殊 token 的完整两两注意力分数，元素数会从 `196²` 变成 `784²`，增至 16 倍。

这里计算的是注意力分数矩阵的元素数。实际耗时和显存还取决于注意力算法、局部窗口、压缩和缓存策略；加入特殊 token 后，矩阵大小也会变化。

高分辨率、动态尺寸和切图可以增加细节入口，但也要保留块的顺序、位置及全图关系。只给几块局部裁剪，可能看清局部文字却不知道它属于哪一栏；只给低分辨率全图，则可能知道布局却读不清内容。这是视觉输入设计中的真实取舍。

## 7.7 初始 patch 数不等于语言模型的视觉 token 数

一个 MLLM 可能先处理多个裁剪，再把相邻特征合并，或用可学习查询压缩成固定数量的表示。因此至少要区分：输入图片数、切图数量、编码器内部 patch 数、连接器输出 token 数。

例如编码器输出 `[B,196,512]`，连接器可以只改宽度得到 `[B,196,2048]`，也可以先压缩到 64 个位置再得到 `[B,64,2048]`。前者保留 token 数，后者改变 token 数，不能用同一个“投影”词掩盖二者差异。

视觉编码器的预训练目标还影响特征用途。分类、图文对比和图像重建对信息保留的要求不同；更宽或更多 token 不自动意味着更可靠的 OCR、计数或空间推理。下一章解释 CLIP 如何用图文配对学习一种适合相似度比较的表示。
