# 03 PyTorch 张量与自动求导

前置：[02 NumPy 基础](./02-NumPy基础.md)。本章解释张量的设备与精度，以及自动求导怎样把损失的变化传回参数。

NumPy 能完成数组计算，但训练模型还需要知道：“为了让误差变小，每个参数应往哪个方向改变？”PyTorch 的张量负责承载数据，自动求导负责沿计算关系求出变化率，优化器再根据这些变化率更新参数。计算、求导、更新是三个不同步骤。

## 3.1 同样是张量，多了设备和梯度属性

PyTorch 的 `Tensor` 也有形状、类型和索引规则。读一个张量时，除了 `[B,N,D]`，还应关注它位于 CPU 还是 GPU，以及是否参与梯度计算。

| 属性或概念 | 含义 | 多模态中的例子 |
| --- | --- | --- |
| `shape` | 各轴的长度 | 图像批次 `[B,C,H,W]` |
| `dtype` | 数值表示方式 | 图像特征用浮点数，token ID 用整数 |
| `device` | 数据所在计算设备 | CPU 或某张 CUDA GPU |
| `requires_grad` | 是否需要对该张量求梯度 | 待学习的浮点权重通常需要 |
| `grad` | 反向传播累积的梯度 | 告诉优化器损失如何随参数变化 |

不同设备上的张量一般不能直接一起运算。`.to(...)` 返回转换后的张量，要接住返回值；它可能涉及数据复制和传输。更低精度能减少某些存储与计算成本，也会改变数值范围或精度，不等于模型在所有硬件上都更快、更稳定。

token ID 是离散索引，不对“第 42 个词改成 42.1”求导；embedding 表中的浮点参数可以学习。这也是数据类型具有计算含义，而不只是节省内存的原因。

### 精度、存储与量化

浮点数用有限位数近似表示实数。FP32 通常每个元素占 4 字节，FP16 和 BF16 各占 2 字节，但两种 16 位格式在范围和精细程度之间采用不同分配。不同运算对数值范围和精度的要求不同；混合精度据此选择数值格式。

量化进一步用较少的离散编码表示一组权重，并借助比例等信息近似还原。4-bit 权重存储不意味着激活、梯度和所有运算都使用 4 bit。模型能否运行还取决于设备、算子支持和运行时内存；比较资源需求时，要分别说明权重存储与计算精度。

## 3.2 导数：输入轻微变化时，输出怎样变化

对函数 `y=w²`，当 `w=3` 时，`w` 稍微增加，`y` 约以每单位 6 的速度增加；导数写成 `dy/dw=2w=6`。这是 `w=3` 处的局部变化率；当 w 改变时，导数 `2w` 也随之改变。

若损失依赖许多参数，把每个参数对应的偏导数放在一起，就是梯度。偏导数的意思是：暂时固定其他参数，只看某一个参数的微小变化。梯度的形状与被求导的参数一致；参数是矩阵，梯度也是同形状矩阵。

梯度为正意味着在当前位置稍微增大该参数，损失通常会增大；梯度为负则相反。因此最简单的梯度下降沿负梯度方向走。梯度为零也不自动意味着找到了理想模型：可能是平坦区域、局部极值，或计算路径已被断开。

## 3.3 链式法则：把局部变化率接起来

设单条样本输入 `x=2`、目标 `t=5`，模型为 `y=wx+b`，损失为 `L=(y-t)²`。取 `w=1,b=0`，得到 `y=2,L=9`。

先看最后一步：`dL/dy=2(y-t)=-6`。再看预测怎样依赖参数：`dy/dw=x=2`、`dy/db=1`。沿路径相乘，得到：

```text
dL/dw = dL/dy × dy/dw = -6 × 2 = -12
dL/db = dL/dy × dy/db = -6 × 1 = -6
```

这就是链式法则：最终误差通过中间计算一步步传回参数。若同一参数通过多条路径影响损失，各路径贡献要相加。真实网络只是把这种关系扩大到许多层和许多张量，不需要为每个参数反复尝试“加一点再跑一次”。

## 3.4 计算图与 backward 的边界

当需要梯度的浮点张量参加可求导运算时，PyTorch 会记录相应关系，构成计算图。前向计算得到输出和损失；对标量损失调用 `backward()`，按链式法则反向计算并累积梯度。它不会自动执行优化器更新。[官方自动求导教程](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)可用于对应这些术语。

参数通常是计算图的叶子张量，默认会保存其 `.grad`；中间结果通常不保留可直接查看的 `.grad`，不代表梯度没有经过它。对非标量输出求导，还需要明确各输出如何组合；训练时常先把逐样本损失归约为标量。

一般一次反向传播后，供该次反向使用的中间缓存会释放。下一步通常重新前向计算，而不是拿同一个损失反复 backward。动态计算图也意味着 Python 条件分支可以影响本次记录的路径。

## 3.5 梯度累积与参数更新不是一回事

`.grad` 默认累加，而不是每次 backward 自动替换。通常一个优化步骤对应“清理旧梯度 → 前向 → 计算损失 → backward → optimizer.step”。这里的清理防止上一步梯度意外混入下一步；更新则改变权重。

梯度累积是有意把多个小批次的贡献合并，最后更新一次，以降低单次前向需要的内存。若两个小批次大小相同、各自损失取平均，想得到它们合并后的平均梯度，应把两份平均损失各按二分之一缩放后再累积。大小不同或有效 token 数不同，权重也应随分母调整，不能机械除以固定次数。

即使分母处理正确，随机层、批次相关层和数值精度也可能使它与直接大批次运行不完全一致。梯度累积并不减少保存模型权重所需的内存，也不意味着参数每个小批次都会更新。

## 3.6 冻结、detach、no_grad 与 eval

这些词经常一起出现，但作用不同：

| 操作 | 主要作用 | 不能据此推断 |
| --- | --- | --- |
| 参数 `requires_grad=False` | 不为该参数计算待更新梯度 | 该模块不再参与前向 |
| `detach()` | 得到与原计算图断开的张量 | 一定复制了独立数据 |
| `no_grad()` 上下文 | 暂时不记录通常的求导图 | 已切换所有层的推理行为 |
| `model.eval()` | 切换 Dropout、BatchNorm 等模块的行为 | 已关闭自动求导 |
| `model.train()` | 切回训练模式 | 已执行一次训练或更新 |

冻结一个模块的参数，不一定能把它的整个前向放进 `no_grad()`：若还要把梯度穿过它传到更前面的可训练模块，切断计算图会改变学习过程。LoRA 冻结基座权重时，基座仍参与前向计算；后续层对可训练适配器的梯度路径仍需保留。

同样，把张量变成 Python 数字或交给 NumPy 再计算，通常不能自动把后续运算接回原来的 PyTorch 求导图。原地修改反向所需的中间值也可能触发错误。阅读损失代码时，要沿参数到损失检查路径是否连续。

## 3.7 从局部梯度走向模型学习

本章的小模型中，梯度告诉我们当前样本希望 `w` 和 `b` 增大。它没有回答该走多远、是否对其他样本也有效、是否只记住训练数据。这些由学习率、数据和评估方式共同决定。

对 MLLM，同一套规则仍成立：图像和文字进入模型，输出与目标形成损失，梯度沿被允许的路径返回视觉模块、连接器或语言模块。冻结哪些参数、在哪些位置计算损失，决定究竟在教模型什么。下一阶段需要理解网络层如何组合，以及为什么训练误差下降不等于泛化能力提高。
