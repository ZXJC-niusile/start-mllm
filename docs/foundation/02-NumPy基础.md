# 02 NumPy 基础：把形状变成数组运算

前置：[01 向量、矩阵与张量基础](./01-向量矩阵与张量基础.md)。本章把列表中的形状概念转成数组操作，重点理解轴、类型和数据布局。

上一章用列表和循环表达矩阵计算。到了实际项目，同一批图像包含成千上万个数字，逐层写 Python 循环不方便。NumPy 用 `ndarray` 表达规则数组，让“对哪个轴做什么运算”直接出现在代码里。它常用于数据处理；PyTorch 延续了很多相似概念，但增加了自动求导和设备管理，两者不能随意混用。

## 2.1 数组除了数值，还有形状和类型

Python 列表可以混装字符串、数字和不同长度的子列表；数值计算通常需要形状规则、元素类型明确的数组。例如 `np.array([[1, 2, 3], [4, 5, 6]], dtype=np.float32)` 表示两行三列的浮点数组，`np` 是 NumPy 的常用别名。

| 属性 | 本例 | 读法 |
| --- | --- | --- |
| `shape` | `(2, 3)` | 第一个轴长 2，第二个轴长 3 |
| `ndim` | `2` | 两个轴，不是只有两个数字 |
| `size` | `6` | 总元素数 |
| `dtype` | `float32` | 每个元素采用 32 位浮点表示 |

整数适合存索引；浮点数适合表示特征、权重和概率；布尔值适合表达“这个位置是否有效”。类型影响精度、范围和内存，不能只看数值是否显示为整数。像素常以 `uint8` 存储，范围是 0～255；做减法和标准化前通常要转成浮点数，以免在无符号整数上发生回绕。浮点运算也有舍入误差，数学上相等不等于机器计算必须逐位相等。

## 2.2 索引是在选择轴，不是在猜数据含义

设 `x` 为上面的 `(2,3)` 数组：`x[0]` 是第一行 `[1,2,3]`，形状 `(3,)`；`x[:,1]` 是第二列 `[2,5]`，形状 `(2,)`。冒号表示沿该轴选择所有位置，索引从 0 开始。

整数索引会去掉相应轴，切片通常保留轴。因此 `x[0:1]` 仍是 `(1,3)`，`x[:,1:2]` 是 `(2,1)`。这在批量模型中很重要：一条样本 `[D]` 与一个样本组成的批次 `[1,D]` 不是同一接口。

布尔索引可以筛选数据，例如 `x[x > 3]` 得到 `[4,5,6]`。它把选出的元素汇集起来，不保留原来的二维布局。对图像筛选像素与在原图上保留空间位置，是两个不同操作。

## 2.3 逐元素运算、矩阵乘法和归约

对数组，`x * 2` 把每个元素乘 2；`x * x` 是对应元素相乘；`x @ w` 才是矩阵乘法。若 `x` 为 `[2,3]`，`w` 为 `[3,4]`，结果为 `[2,4]`。不要把 Python 列表的重复操作和数组乘法混为一谈。

归约（reduction）把一个轴上的多个数合并，例如求和、均值、最大值。对本例：

| 表达式 | 数值 | 结果形状 | 消去的轴 |
| --- | --- | --- | --- |
| `x.sum()` | `21` | 标量 | 所有轴 |
| `x.sum(axis=0)` | `[5,7,9]` | `(3,)` | 行轴 |
| `x.sum(axis=1)` | `[6,15]` | `(2,)` | 列轴 |
| `x.sum(axis=1, keepdims=True)` | `[[6],[15]]` | `(2,1)` | 计算沿列轴，保留长度 1 |

“沿 axis=0”不是“只取第 0 行”，而是让这个轴变化，把对应位置合并。若输入 `[B,N,D]`，沿 `N` 求均值得到 `[B,D]`，含义是把每张图的多个 token 汇成一个向量。形状变小的同时，也丢失了逐 token 的直接访问能力。

### 均值、标准差与归一化

均值是数值之和除以数量，用来表示中心位置。离均值有多远则反映分散程度：对 `[1,3]`，均值为 2，偏差为 `[-1,1]`；按总体方差定义，把偏差平方后求平均得到 1，再开平方得到标准差 1。这里使用除以元素数的定义，不是统计估计中常见的除以 `n-1` 的样本方差。

标准化把每个数减去均值，再除以标准差，本例得到 `[-1,1]`。它与 L2 归一化不同：后者把整个向量除以长度，例如 `[3,4]` 的长度为 `sqrt(3²+4²)=5`，归一化后是 `[0.6,0.8]`。前者调整中心与尺度，后者保留方向并固定长度。遇到“归一化”时，应先查具体公式、计算轴和零分母处理，不能只按名称判断。

## 2.4 广播：按规则复用，不是任意凑形状

给 `[2,3]` 的 `x` 加上 `[3]` 的偏置 `[10,20,30]`，结果是 `[[11,22,33],[14,25,36]]`。偏置对每一行复用，不需要手工拼出两份。[NumPy 广播规则](https://numpy.org/doc/stable/user/basics.broadcasting.html)从最右侧对齐形状：对应长度相等，或其中一个为 1，才兼容；缺少的前导轴按长度 1 处理。

例如 `[B,N,D] + [D]` 给每个 token 加相同偏置；`[B,N,D] + [B,1,D]` 给同一张图内的 token 加同一向量。后者中长度 1 的轴告诉程序在哪个方向复用。

广播也可能产生形状合法、含义却错误的结果。`[B,1] - [B]` 会得到 `[B,B]`，不是预想的逐样本误差 `[B,1]`：右侧实际按 `[1,B]` 对齐。若把这个结果直接求均值，程序能运行，计算目标却变了。读模型代码时，应同时核对形状和每个轴的含义。

## 2.5 reshape 与转置解决不同问题

`reshape` 按指定顺序重新组织元素，要求元素总数不变；`-1` 表示根据其余轴推算唯一缺失的长度。将 `[2,3]` 改为 `[3,2]`，不等于交换行列。对本例，默认顺序的 reshape 得到 `[[1,2],[3,4],[5,6]]`，转置却得到 `[[1,4],[2,5],[3,6]]`。

图像数组常采用 `[H,W,C]`，某些模型接口需要 `[C,H,W]`。这里应交换轴次序，不能仅把三个数字填进 reshape。多维数组的 `.T` 会反转轴顺序，也不能一概当作“只交换最后两个轴”；读代码时优先看明确的轴排列。

`stack` 会新增一个轴：两张 `[H,W,C]` 图按批轴堆叠，得到 `[2,H,W,C]`。`concatenate` 沿已有轴连接：把两个 `[N,D]` token 序列沿第 0 轴连接，得到 `[2N,D]`。前者表达两张样本，后者表达更长序列，语义不能互换。

## 2.6 视图、复制与数据归属

变量赋值 `y=x` 不会自动复制数组。基本切片通常产生共享底层数据的视图，修改切片可能改变原数组；需要独立数据时使用 `.copy()`。高级索引通常返回副本；reshape 能否共享内存取决于布局，不能仅凭函数名判断。[官方视图与复制说明](https://numpy.org/doc/stable/user/basics.copies.html)解释了这些区别。

例如先取图像的一块区域，再原地涂色，如果它是视图，整张源图也可能被改动。用于多个样本的共享预处理数据尤其需要明确归属。广播通常避免实际复制小输入，但运算输出仍可能很大；“没有写循环”不等于“没有内存成本”。

## 2.7 接回多模态数据流

读一段图像预处理时，可以顺着四件事理解：输入是什么布局；什么时候转浮点；归一化沿哪个轴；什么时候加入批轴或交换通道轴。把 `[H,W,C]` 转成 `[B,C,H,W]` 只改变表示接口，视觉编码器才负责进一步提取特征。

同样，数组归一化只是数值操作，不会自动产生语义。接下来学习 PyTorch 时，这套“形状、类型、轴与数据归属”的读法仍然适用；新的问题是，哪些计算需要被记录下来，以便求出参数应如何变化。
