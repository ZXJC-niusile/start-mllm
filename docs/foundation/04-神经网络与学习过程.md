# 04 神经网络与学习过程

前置：[03 PyTorch 张量与自动求导](./03-PyTorch张量与自动求导.md)。本章解释网络层如何组合、损失怎样定义，以及一次参数更新为什么不等于学会一个任务。

一个模型可以看作带可调参数的函数：输入 `x`，输出预测 `fθ(x)`，其中 `θ` 表示所有待学习参数。学习过程根据给定数据和损失目标调整这些参数。函数结构决定能表达什么，损失决定偏好什么，数据决定实际看到了什么。

## 4.1 从线性层到多层网络

线性层把输入特征组合成输出：数学约定可写为 `y=xW+b`。若输入为 `[B,D输入]`，权重为 `[D输入,D输出]`，输出是 `[B,D输出]`，偏置 `[D输出]` 对每条样本复用。PyTorch `nn.Linear` 将权重存为 `[D输出,D输入]`，因此实际表达为 `xAᵀ+b`；读参数形状时要分清存储约定。

假设输入是两个已经数值化的图像特征，第一层把 `[B,2]` 变成 `[B,4]`，下一层把 `[B,4]` 变成 `[B,3]`，最后的 3 个数可以表示三个类别的分数。中间 4 个分量叫隐藏表示，它们由训练形成，各分量没有预先指定的“颜色”“形状”等含义。

仅堆叠线性层并不能获得新的非线性表达：`(xW₁+b₁)W₂+b₂` 仍能合并成一个仿射变换。因此层之间通常加入非线性激活，例如 `ReLU(z)=max(0,z)`。其他激活会采用不同的平滑或门控变换；首次阅读先理解为什么需要非线性，具体函数随模型配置查阅。多层感知机（MLP）通常由这样的线性变换和非线性组成。

宽度是每层表示的分量数，深度是层的数量；它们与 token 数、批大小不同。网络更大并不自动更适合当前数据，计算和过拟合风险也会变化。

## 4.2 参数、超参数和状态

权重、偏置属于模型参数，通过梯度更新。学习率、批大小、训练轮数、网络宽度属于超参数，由配置或选择过程确定，不会因为调用 backward 就自动变得合适。优化器还可能维护动量等状态，用来综合过去的梯度。

模型输出是本次输入的计算结果，不是参数。梯度也不是模型权重，而是当前目标对权重的变化率。保存一份用于推理的权重，与保存可完整恢复训练的 checkpoint 不同：后者通常还需要优化器、学习率调度器、步数以及相关随机状态。

随机初始化让不同单元有机会学习不同作用。预训练模型则从已学习的参数开始，后续微调适配任务；这不意味着只要换一份数据，就会保留所有原有能力。

## 4.3 预测分数如何变成损失

回归任务预测连续值，例如金额或温度，常用平方误差。若真实值是 5，预测是 2，单样本平方误差是 9；若预测变为 4，误差变为 1。损失数值衡量的是所选目标，不是“理解程度”。

分类任务通常先输出 logits，即未归一化分数。例如 `[2,1,0]` 对三个类别分别打分。softmax 将分数变成总和为 1 的正数：第 `i` 类概率是 `exp(zᵢ)/Σⱼexp(zⱼ)`，这里 `exp` 是指数函数，`Σ` 表示求和。为稳定计算，可先从所有分数减去同一个最大值，概率不变。

若正确类别概率为 `p`，单样本交叉熵是 `-ln(p)`，`ln` 是自然对数。`p=0.8` 时约为 0.223，`p=0.2` 时约为 1.609；给正确类别更高概率会减小损失。实际 PyTorch `CrossEntropyLoss` 接收 logits，内部完成相应计算，不能把已经 softmax 的概率当作通常的 logits 再传一次。标签可采用类别索引等接口规定的形式，形状与类型必须符合所用模式。[官方定义](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)列出了输入约定。

准确率看最终选中的类别是否正确，交叉熵还关心模型对正确类别分配了多少概率。两者不等价：两个模型可能预测都正确，但置信程度不同；低平均损失也可能掩盖少数重要类别的失败。

## 4.4 一次更新究竟改变了什么

沿用上一章 `x=2,t=5,w=1,b=0` 的模型，损失梯度为 `dL/dw=-12`、`dL/db=-6`。最简单的随机梯度下降（SGD）规则是 `参数 ← 参数 - 学习率 × 梯度`。取学习率 0.1，更新后 `w=2.2,b=0.6`，预测恰好成为 5。

本例中学习率 0.1 恰好使这条样本的误差归零。换用其他数据或模型后，需要重新选择学习率：步子过大可能越过低损失区域甚至发散；过小则进展缓慢。Adam 等优化器还会维护梯度及梯度平方的移动平均，用这些历史量调整更新尺度，因此不同参数的更新不只是同一个固定步长乘当前梯度。完整训练循环的职责分工见 [PyTorch 优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)。

前向计算、损失、反向传播和优化器更新按顺序发生。`model.train()` 仅切换模块模式；`backward()` 仅计算梯度；`optimizer.step()` 才更新它管理的参数。高层 `Trainer` 把这些步骤包装起来，基本原理并没有消失。

## 4.5 batch、step 与 epoch

一个 batch 是本次一起处理的样本集合；一次 optimizer step 是一次参数更新；一个 epoch 是按既定数据迭代方式遍历一轮训练数据。若 100 条样本、batch size 为 10、不丢末批、无梯度累积，通常每轮有 10 次更新。加入梯度累积后，前向批次数与更新次数就不相等。

逐样本损失最终如何求平均也很重要。文本序列长度不同时，“每个样本权重相同”与“每个有效 token 权重相同”是不同目标。padding 只是凑齐形状，不能成为模型必须预测的无意义答案。有效位置的掩码和损失分母共同决定优化方向。

## 4.6 为什么训练集不能证明学会了

模型可能记住训练数据中的模板、背景或答案频率。训练损失下降，只证明对已见样本的目标更匹配；泛化是对未参与参数更新、且符合目标应用分布的数据表现如何。

train 用来更新参数，validation 用来比较方案和调超参数，test 用于最终验收。反复查看 test 再改方案，也会让 test 失去独立性。同一张图的裁剪、同一票据的多个问题、同一文档的不同页，可能共享信息，应按来源分组再划分，而不是只随机打散 JSONL 行。

欠拟合可能表现为训练和验证都差；过拟合常表现为训练继续改善而验证恶化，但这些现象也可能来自标签错误、预处理不一致或分布变化，不能只看一条曲线下结论。为了改善对新样本的表现，可以限制模型对训练样本的拟合方式。正则化是这类约束的统称，常见方法各有机制：

| 方法 | 做了什么 | 阅读时要分清什么 |
| --- | --- | --- |
| 权重衰减 | 更新时加入使权重缩小的作用 | 它约束参数，不是减少样本数量；与损失中直接加入 L2 惩罚是否等价取决于优化器 |
| Dropout | 训练时随机将部分激活置零，并按约定缩放 | 通常不永久删除神经元；推理时关闭随机丢弃 |
| 早停 | 根据独立验证表现选择停止时机或保留 checkpoint | 不能反复用最终测试集来选停止点 |

例如保留概率为 0.5 的常见 Dropout 实现，会把保留的激活乘 2，使单个激活的期望尺度保持不变；一次前向中的具体值仍会变化。实现定义见 [PyTorch Dropout](https://docs.pytorch.org/docs/2.9/generated/torch.nn.Dropout.html)。这些方法需要在任务上验证，不能弥补标签错误或训练与测试来源泄漏。

## 4.7 回到 MLLM：什么参数在学，什么位置被监督

语言模型把“分类”重复到词表中的下一 token 选择。监督微调往往只在 assistant 回答位置计算目标损失；用户问题和视觉输入是条件，不能因为它们参与前向就认为都应被当作答案监督。

全量微调更新大量基座参数；冻结视觉编码器只训练 Projector，是另一种参数选择；LoRA 在选定变换旁增加低秩可训练分支，降低部分可训练状态的规模。LoRA 仍需损失、反向传播和优化器，也不自动消除视觉 token、激活与基座权重的成本。

理解这些概念后，再读[第四章数据、训练与微调](../chapter4/第四章%20数据、训练与微调.md)，就可以分别追问：输入和标签是什么、损失在哪些位置计算、哪些参数更新、用什么独立数据验证收益。实际训练流程留待配套实践阶段。
