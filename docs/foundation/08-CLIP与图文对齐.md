# 08 CLIP 与图文对齐

前置：[07 CV 基础与 ViT](./07-CV基础与ViT.md)。图像和文本都能变成向量，但来自不同编码过程。本章解释怎样通过配对目标学习可比较的表示，以及这种匹配能力的边界。

## 8.1 “对齐”究竟想解决什么

假设一张猫的图片和一句“窗边的一只猫”分别经过两个随机编码器，最后都得到 512 个数。两者维度一致，可以计算点积，但随机编码器尚未学到图文之间的对应关系。

在本章，对齐指通过配对数据和学习目标，让相关图文在所用相似度下更容易匹配，而不相关候选更难匹配。它不要求每个向量分量都对应一个人工概念，也不表示每个词都已定位到图中某个区域。局部定位、整体匹配和生成式问答是不同能力。

## 8.2 CLIP 的双塔数据流

[CLIP 原论文](https://arxiv.org/abs/2103.00020)使用图文配对学习可比较的表示。一侧是图像编码器，一侧是文本编码器；各自提取全局特征，经投影进入共同宽度的空间，再归一化并比较相似度。视觉骨干可有不同选择，不能把 CLIP 固定等同于某一种 ViT。

这里用 `u` 表示图像向量、`v` 表示文本向量。对非零向量分别除以自身长度，得到单位向量后，点积就是余弦相似度。它测量方向接近程度，减少向量长度本身对比较的影响。

“双塔”意味着两侧可以各自编码，并在后面计算匹配分数，不是先把图文拼成同一序列做全面交互。用于检索时，可以预先编码一批候选，查询到来后再比较；最终效率仍取决于候选规模和检索实现。

## 8.3 一批配对怎样形成一个分类问题

设一批有 `B` 个已知配对 `(图片ᵢ,文本ᵢ)`。把所有图像向量和所有文本向量交叉比较，得到 `[B,B]` 分数矩阵，行是图像、列是文本，对角线是提供的配对。

在简化目标中，每张图要从这批文本中找回自己的配对，每段文本也要从这批图片中找回自己的配对。对一行做 softmax，就是图到文的候选概率；对一列做 softmax，就是文到图的候选概率。分别计算正确配对的负对数概率，再对两方向求平均，形成对称对比目标。

这与[基础篇 04](./04-神经网络与学习过程.md)的分类损失有关，但“类别”在这里是当前批次中的候选编号，而不是固定的一套猫狗标签。每次批次不同，候选也会变。

## 8.4 两对样本的小数值解释

为说明计算，人工设置两个图像单位向量和两个文本单位向量都为 `[1,0]`、`[0,1]`，同编号为配对。暂取缩放系数 1：

```text
                 文本 1    文本 2
图片 1              1         0
图片 2              0         1
```

每行正确配对概率为 `exp(1)/(exp(1)+exp(0))≈0.731`，单方向每条损失约为 0.313。由于矩阵对称，另一方向相同，对称平均也约为 0.313。这些结果由上面给定的单位向量计算而来，其中 0.731 表示当前候选集合中的配对概率。

若所有图文都输出同一个单位向量，矩阵所有位置分数相同。每行正确候选只能得到 `1/B`，损失为 `ln(B)`；当 `B=2`，约为 0.693。把所有表示压成一样，不能完成区分配对的目标。

一般可写缩放后分数为 `相似度/τ`，其中正数 `τ` 是温度；也可用正的尺度因子乘相似度。温度越低，相同分数差距对应的概率分布越尖锐。它影响损失与梯度，不能凭概率更尖锐就宣称语义更正确；原始 CLIP 学习相应的 logit 尺度。

## 8.5 正负样本只是数据构造的约定

简化的批内目标把非配对项当作负候选，但它们未必语义错误。两张不同猫图可能都符合“一只猫”，同一张图也可能有多种正确描述；这会形成假负例。重复、噪声配对和过于笼统的文本都会改变学习信号。

相反，数据可能给模型留下捷径：水印、网站模板或背景与文本高度相关，模型就可能利用它们，而非任务真正关心的细节。因此配对数量多不等于监督准确，更不等于空间关系、计数和小字读取都被覆盖。

全局匹配目标通常不直接给出“哪个词对应哪个框”的标注。模型可能学到有用的区域信息，但不能把整体对齐成绩当作精确 grounding 的验收。

## 8.6 零样本分类与检索在做什么

做零样本分类时，可以把类别写成文本描述，分别编码，再让图像与这些候选比较。所谓零样本，是针对目标任务没有使用相应的监督训练样本来拟合该分类器，不是模型从未学习过任何图文知识。

候选写法会影响分数。例如“猫”和“这是一张猫的照片”并不是必然等价的输入。模型若只在猫、狗两类间做选择，即使图片是汽车也可能选出一个分数较高的类；候选 softmax 概率是相对这组候选的比较，不是经过校准的“图片一定属于猫”的概率。加入候选也会改变分母。

检索则把候选换成实际图片或文字集合，返回较相似的项目。它能帮助找资料或筛选数据，但不会自动生成解释，更不能单凭相似度解决数值计算、细致关系判断或事实核验。

## 8.7 为什么 CLIP 不是会聊天的 MLLM

CLIP 的输出可以用于相似度排序，其核心目标不包含逐 token 生成回答。把一张图片编码成向量，再选最相似的描述，与根据问题生成一段未预先列出的答案，是不同计算链。

生成式 MLLM 可以借用经过图文学习的视觉编码器，但通常还需要连接器、语言模型和相应训练。此时读取的可能是视觉塔内部的 patch 特征，而不是 CLIP 用于全局检索的最终向量；它们的形状、层位置和用途要分别确认。

“CLIP 已经对齐”也不意味着其特征可以直接当作任意 LLM 的输入 embedding。CLIP 的共同空间服务于自己的匹配目标，LLM 的输入空间服务于上下文生成；两者之间仍需适配并验证。下一章把这条链从图像一直接到文本回答。
