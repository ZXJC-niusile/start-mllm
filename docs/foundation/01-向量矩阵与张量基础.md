# 01 向量、矩阵与张量基础

读第三章时，你会遇到“把视觉特征从 `[B,N,1024]` 投影到 `[B,N,4096]`”。这句话里哪些数字代表图片，哪些代表 token？为什么乘一个矩阵就能改变最后一维，却没有增加 token？本章用能手算的数据回答这些问题。

**前置要求**：会读 Python 列表、索引、循环和函数；会按 [基础篇 00](./00-环境命令行与Python项目基础.md) 从仓库根目录运行脚本。只用 Python 标准库和 CPU，不安装 NumPy/PyTorch，不下载模型，不调用 API。

**完成标准**：你能解释 `[B,N,D]` 的三个轴，手算一次投影，并在运行前判断错误形状。只看到脚本输出 PASS 还不够，请独立完成末尾自测。

## 1.1 从一个数到一批 token

在本章的深度学习数组语境中，张量（tensor）是按多个轴组织的数值数组。先不用学习更一般的数学张量定义。

| 对象 | 例子 | 形状（shape） | 含义 |
| --- | --- | --- | --- |
| 标量（scalar） | `7` | `[]` | 一个数，没有轴 |
| 向量（vector） | `[1,2,0]` | `[3]` | 一个轴，含 3 个数 |
| 矩阵（matrix） | `[[1,2,0],[0,1,3]]` | `[2,3]` | 两个轴，2 行、3 列 |
| 三维张量 | 两个这样的矩阵放在一个列表里 | `[2,2,3]` | 三个轴，每个轴长度依次为 2、2、3 |

**轴数和轴长要分开**：“3 维向量”常指有 3 个分量的向量，它仍只有一个轴；`[2,2,3]` 才是这里说的三维数组。形状相同也不保证含义相同，要为每个轴写上名字。

假设一个视觉编码器已经为每张图片产生了 2 个视觉 token，每个 token 用 3 个数字表示。把两张图片放入一个批次（batch），得到 `F`，形状写作 `[B,N,D]=[2,2,3]`：

- `B` 是批大小，这里是 2 张图片；
- `N` 是每张图片的 token 数，这里是 2；
- `D` 是每个 token 的特征数，这里是 3。

下面是**完整可运行的 Python**。索引从 0 开始，先选图片，再选 token，最后选分量。

```python
F = [
    [[1, 2, 0], [0, 1, 3]],  # 第 1 张图的两个 token
    [[2, 0, 1], [1, 1, 1]],  # 第 2 张图的两个 token
]
print(F[0])        # [[1, 2, 0], [0, 1, 3]]：形状 [N,D]
print(F[0][1])     # [0, 1, 3]：形状 [D]
print(F[0][1][2])  # 3：标量
```

这些数是为了手算而编的特征，**不是像素，也不是运行视觉编码器得到的结果**。真实特征通常是浮点数，单个分量不一定对应人能命名的属性。

普通文本 token ID 是词表里的离散索引，例如编号 42；嵌入（embedding）把索引映射成向量。这里的视觉 token 则已经是连续特征向量，不能把它当成“词表里的第 3 个词”。后续章节会继续讲 token ID 与 embedding 的区别。

## 1.2 三种“乘法”究竟算什么

令 `u=[1,2,3]`、`v=[4,5,6]`。

- **逐元素乘（elementwise product）**：对应位置分别相乘，得到 `[4,10,18]`，保留 3 个分量。
- **点积（dot product）**：对应位置相乘，再把结果相加，得到 `1×4+2×5+3×6=32`，输出一个标量。
- **矩阵乘法（matrix multiplication）**：输出的每个元素，都是左边一行与右边一列的点积。

以第一张图的特征矩阵 `X=[[1,2,0],[0,1,3]]` 为例，它是 `[2,3]`。选择权重矩阵 `W=[[1,0],[0,1],[1,-1]]`，形状 `[3,2]`。`W` 的两列分别是 `[1,0,1]`、`[0,1,-1]`，规定了两个输出分量如何组合输入的三个分量。

`Y=XW` 的四个元素必须分别算出来：

| 输出位置 | 左边一行 · 右边一列 | 结果 |
| --- | --- | --- |
| 第 1 行第 1 列 | `1×1 + 2×0 + 0×1` | `1` |
| 第 1 行第 2 列 | `1×0 + 2×1 + 0×(-1)` | `2` |
| 第 2 行第 1 列 | `0×1 + 1×0 + 3×1` | `3` |
| 第 2 行第 2 列 | `0×0 + 1×1 + 3×(-1)` | `-2` |

所以 `Y=[[1,2],[3,-2]]`，形状 `[2,2]`。每行仍对应原来的一个 token，只是每个 token 从 3 个分量变成了 2 个。

**形状规则**：`[N,D输入] × [D输入,D输出] → [N,D输出]`。内侧两个长度必须相同，因为每次点积要逐项配对；输出保留左边的行数和右边的列数。若 `W` 错写成 `[2,3]`，这里就不能相乘，不能靠“数字总数一样”解释过去。

本章数学中的 `XW` 表示矩阵乘法。Python 原生列表不支持矩阵 `@`，列表 `*` 也不是逐元素乘。配套脚本用循环明确实现这些运算；不要直接对上述列表写 `X @ W`。之后使用 PyTorch 张量时，`@`/`matmul` 才提供对应的矩阵运算，见 [官方 matmul 文档](https://docs.pytorch.org/docs/2.9/generated/torch.matmul.html)。

## 1.3 转置为什么会出现

转置（transpose）把二维矩阵的行、列交换。`X` 的形状为 `[2,3]`，`X.T` 是 `[[1,0],[2,1],[0,3]]`，形状变为 `[3,2]`。

现在计算 `X X.T`，等价于把 `X` 的每个 token 与每个 token 做点积：

- 位置 `(0,0)`：`1²+2²+0²=5`；
- 位置 `(0,1)`：`1×0+2×1+0×3=2`；
- 位置 `(1,0)`：同一对向量反向配对，仍是 `2`；
- 位置 `(1,1)`：`0²+1²+3²=10`。

结果是 `[[5,2],[2,10]]`，形状 `[N,N]`。这里两个轴都是 token，**已经没有特征轴**。虽然它恰好与上节的 `Y` 都是 `[2,2]`，二者含义完全不同。

点积可作为相容性分数，但会受向量长度影响：第二个向量与自己的点积更大，不能据此断言它“语义更好”。这也还不是完整注意力：查询/键投影、缩放、mask 和 softmax 等步骤需另学。本节只为以后读懂 token 两两打分的形状做准备。

## 1.4 批量投影：B 和 N 都不要丢

对 `F` 中的两张图片分别应用同一个 `W`，第二张图片同样可手算：`[2,0,1]W=[3,-1]`，`[1,1,1]W=[2,0]`。因此批量结果是：

`Y=[[[1,2],[3,-2]], [[3,-1],[2,0]]]`。

整体形状变化为 **`[B,N,D输入] × [D输入,D输出] → [B,N,D输出]`**，本例是 `[2,2,3] → [2,2,2]`。这里权重跨图片和 token 共享，不是把两张图片混合。仅这个投影不让一个 token 读取另一个 token；上下文交互由其他模块完成。

PyTorch 的 `matmul` 对这样的三维输入按最后两个轴做矩阵乘法，让二维 `W` 在批维复用，这是广播（broadcasting）的一种情况，见 [批量矩阵乘法规则](https://docs.pytorch.org/docs/2.9/generated/torch.matmul.html)。配套脚本用显式循环展示复用，不实现通用广播。

第三章的 Projector（投影层）可以把 `D输入=1024` 换成 `D输出=4096`；本例只把数字缩小方便检查。若你随后读到 `nn.Linear(3,2)`，注意 PyTorch 将其权重存为 `[输出,输入]=[2,3]`，计算时转置，并默认加入偏置，即 `x A.T + b`。本文的 `W` 采用 `[输入,输出]`，且省略偏置；两种约定不要混用。参见 [Linear 官方定义](https://docs.pytorch.org/docs/2.9/generated/torch.nn.Linear.html)。

**形状匹配只说明接口能接上，不说明语义已经对齐。** 我们随手写的 `W` 能算出正确形状，却没有让语言模型学会看图。训练如何让视觉表示变得可用，回到第二、三章再讲。

## 1.5 为什么要保留多个视觉 token

如果过早把整张图片只压成一个向量，后续模块便无法直接按原来的多个位置读取特征。保留一组视觉 token，给后续模型提供了更细粒度的信息入口；是否真正保住文字或位置细节，仍取决于编码、训练和压缩方式。

以 [ViT 论文 §3.1](https://arxiv.org/abs/2010.11929) 的固定切块思路为简化例子：一张 `4×4` 图按 `2×2`、不重叠且不补边的块切开，得到 `(4/2)×(4/2)=4` 个 patch（图像块）。每块表示成长度为 3 的向量后，单图形状是 `[4,3]`，两张图是 `[2,4,3]`。三通道的原始像素块却包含 `2×2×3=12` 个数，**块的原始像素数与投影后的特征宽度不是一回事**。

把图改成 `8×8`、块仍为 `2×2`，初始 patch 数变成 16，是原来的 4 倍。相同 `D` 下，要存的特征数也增加 4 倍。本例的两两打分矩阵则从 `4×4=16` 个元素变为 `16×16=256` 个元素。这里只数矩阵元素，不能由此直接断言整模型耗时一定增加 16 倍。

实际模型还可能有特殊 token、动态分辨率、切图、合并或重采样；**初始 patch 数不一定等于最终送入 LLM 的视觉 token 数**。本章只固定不重叠切块来练习数轴长，更多机制见 [第二章](../chapter2/第二章%20视觉编码器与跨模态对齐.md)。

## 1.6 运行、改动、解释

从仓库根目录运行配套的 [标准库脚本](./code/01_tensor_shapes.py)：

```bash
python docs/foundation/code/01_tensor_shapes.py
```

预期输出（以下是输出记录，不是命令）：

```text
dot: 32
elementwise: [4, 10, 18]
X @ W: [[1, 2], [3, -2]]
F shape: (2, 2, 3)
Y shape: (2, 2, 2)
Y: [[[1, 2], [3, -2]], [[3, -1], [2, 0]]]
X @ X.T: [[5, 2], [2, 10]]
self-test: PASS (values, shapes, batch isolation, invalid inputs)
```

脚本的形状函数用元组输出，如 `(2,2,3)`，与正文的 `[2,2,3]` 表示同一组轴长。`X @ W` 是输出标签；实际调用的是脚本中的 `matmul` 函数。

打开脚本，顺着 `dot → matmul → project_batch` 读一遍：最内层把一行和一列配对，中间层遍历输出行列，最外层遍历图片。自检还会故意传入不等长向量、参差列表和错误权重，确认程序拒绝它们，避免 `zip` 静默丢掉多余数据。

**动手改一次**：先保存原脚本的副本。把 `W` 改成 `[[1],[1],[1]]`，让每个 token 的三个分量求和。运行前写下新形状和完整数值，再更新有关投影输出的断言；点积、逐元素乘、`X X.T` 的断言不应改变。不要为了得到 PASS 而删除断言。

若出现 `AssertionError`，比较“预期值”和“实际值”；若出现“内侧维度必须相等”，先写出两个输入的形状，检查是否把 `W` 的行列写反。Python 标准库版本没有 `.shape` 属性，不要照抄 PyTorch 语法到列表上。

## 1.7 自测：先回答，再看解析

1. `F` 是 `[2,4,3]`，`F[1][2]` 是什么形状？它代表什么？这里总共有多少个数？
2. `u=[2,-1]`、`v=[3,4]` 的逐元素乘与点积分别是什么？哪个保留了特征轴？
3. 输入 `[2,4,3]` 使用权重 `[3,5]`，输出形状是什么？权重 `[4,5]` 为什么不能替代它？
4. 1.6 节把权重改为一列后，完整输出是什么？为什么 `N` 不变？
5. 两张图分别有 4 和 6 个视觉 token，能直接写成一个规则的 `[2,N,D]` 吗？若把 token 数从 4 增为 16，`D` 会自动变大吗？
6. 一个随机 Projector 输出了 `[B,N,4096]`，而 LLM 需要的特征宽度也是 4096。能否据此确认它会回答图像问题？

### 答案与常见误解

1. `[3]`，第 2 张图的第 3 个 token 的特征向量；总计 `2×4×3=24` 个数。`F[1][2]` 不是“第 2、3 个特征”，索引次序必须跟轴的定义走。
2. `[6,-4]` 与 `2`。逐元素乘保留长度为 2 的特征轴；点积求和后变成标量。
3. `[2,4,5]`。权重第一维必须与输入特征数 3 配对，不能拿 token 数 4 来凑。B、N 是被保留的轴。
4. `[[[3],[4]], [[3],[3]]]`，形状 `[2,2,1]`。每个 token 仍单独计算，只减少了输出分量；`[3]` 是长度 1 的向量，不是标量 `3`。
5. 不能直接得到规则的同长数组；可以分别处理，或设计补齐与有效位置标记，让后续运算忽略补齐部分。具体 mask 用法留到后续。`N` 与 `D` 独立，增加 token 个数不会自动增加每个 token 的特征数。
6. 不能。形状检查不能替代训练与任务评测。本章的手写 `W` 就是“形状正确但没有学到图文语义”的例子。

能解释以上结果后，可先读 [LLM 基础速通](../llm-基础速通.md)，用矩阵乘法理解注意力的输入和输出，再读 [第二章的视觉 token](../chapter2/第二章%20视觉编码器与跨模态对齐.md)，再对照 [第三章的 Projector](../chapter3/第三章%20多模态生成架构.md)。NumPy、自动求导和完整注意力仍是后续内容，本章没有覆盖它们；做 API 图文问答也不要求先学完这些框架。
