## 一、为什么长图是多模态系统里的典型难点

长截图、网页、票据和合同页面常同时包含全局布局与局部细节，是文档类应用的重要输入形式。

长图难，不是因为模型“完全看不懂”，而是因为长图天然会把几个问题叠在一起：

- 内容很多
- 小字很多
- 结构复杂
- 缩小后细节损失严重
- 直接整图输入成本高

这类问题如果处理不好，会直接让模型表现从“偶尔不稳”变成“系统性不准”。

## 二、缩放什么时候会丢失任务信息

整图缩放可以用于快速了解布局，但是否适合抽取细节，取决于缩放后的可辨认程度与模型的原生预处理。

如果你把一张超长截图直接等比例缩小，通常会发生：

- 字体变得不可辨认
- 表格线和边界消失
- 小图标和角标丢失
- 阅读顺序变得模糊

如果目标字段在预处理后已不可辨认，应先调整输入方案。若信息仍清楚但回答错误，还需要检查模型与任务适配，不能把所有错误都归因于缩放。

## 三、长图处理的三个基本策略

### 1. 整图粗读

先让模型对整张图做高层次摘要，例如：

- 这是一张什么页面
- 大致分成几个区域
- 页面主要任务是什么

这一层不追求细节，只建立全局认知。

### 2. 切块细读

把长图按区域或固定窗口切成多个小块，逐块分析：

- 每块有什么内容
- 是否有关键字段
- 哪块最值得继续深挖

### 3. 汇总归纳

把每块摘要重新汇总成最终答案，必要时加规则校验。

这本质上是一种应用层“分层阅读”。要区分它与模型内部的高分辨率策略：例如 [InternVL 1.5 对应论文](https://arxiv.org/abs/2404.16821) 的动态切块，和 [Qwen2.5-VL 技术报告](https://arxiv.org/abs/2502.13923) 的动态分辨率处理；本专题不是这些模型预处理器的复现。

## 四、切块策略怎么选

### 1. 固定窗口切块

适合结构相对规整的长图，例如长网页、长后台列表。

优点：

- 实现简单
- 易于批处理

缺点：

- 可能把关键区域切断

### 2. 带重叠窗口切块

在相邻窗口之间保留一定重叠区域，用来减少边界信息丢失。

适合：

- 表格
- 长文档
- 关键字段跨块分布的页面

### 3. 版面感知切块

根据页面结构来切，例如按：

- 标题区
- 正文区
- 表格区
- 侧栏区

这种方式可以保留段落或表格的完整性，但依赖版面识别质量；识别错误可能切错区域。规整页面上的固定窗口也可能更简单、成本更低。

### 重叠与合并需要一起设计

相邻块重叠可以保留跨边界的一行文字，也可能让同一字段被识别两次。例如订单总计同时出现在块 A 的底部和块 B 的顶部，汇总时不能把它们当作两笔订单相加。应保留原图坐标、块编号和字段来源，以位置及内容判断是否重复。

切块还可能分开表头与数值。仅把局部数字交给汇总步骤，会丢失“这一列代表什么”。可携带表头上下文，或在关系不明时回读更大区域。切块解决局部可见性，合并负责恢复跨块关系，两者要同时检查。

## 五、一个实战案例：长截图报错分析

> 与正文 [第九章第四节](../chapter9/第九章%20从单模态%20Agent%20到多模态%20Agent.md#四一个典型案例截图助手-agent) 互补：第九章侧重 Agent 结构和工作流设计，这里侧重切块策略和分层阅读。

假设用户提供的是一张很长的后台报错截图，里面可能同时包含：

- 顶部导航
- 中间报错提示
- 底部日志信息

这时候建议工作流是：

1. 整图摘要，判断页面类型和大致结构
2. 按垂直方向切成 3 到 6 段
3. 对每段单独问“是否包含错误信息或关键提示”
4. 收集最相关的块，再汇总生成答案

这是一条待评估的候选路线。切成几段应由字的大小、区域边界和输入预算决定，不能把 3～6 段当作固定最优值；还需与模型原生整图处理比较遗漏与耗时。

## 六、一个实战案例：长文档字段抽取

如果目标是从长文档中抽字段，建议把任务拆成两类：

### 1. 定位类问题

例如：

- 哪一段包含合同金额
- 哪个区域有日期
- 是否有签章区域

### 2. 抽取类问题

在定位到局部区域后，再做字段提取。

“先定位、再抽取”可以把资源集中到相关区域，但定位漏检会让后续抽取无法看到答案。定位不确定时，应扩大检索范围或回读整图。

## 七、一个实用的层级化 Prompt 思路

你可以把长图处理拆成三层 Prompt：

### 层 1：全局摘要

```text
请概括这张长图的页面类型、主要结构和核心内容，不需要细节。
```

### 层 2：局部切块分析

```text
请分析这一块区域，提取其中的关键文字、字段、报错信息或重要元素。
```

### 层 3：最终汇总

```text
根据整图摘要和各块分析结果，输出最终结论。如果部分信息不确定，请明确说明。
```

这个层级化方式很适合和 Agent 结合。

## 八、固定工作流与 Agent 如何选择

分步处理既可以由固定程序执行，也可以让模型动态决定下一步。若页面结构固定，可先使用确定的切块与合并流程；只有需要根据中间观察改变策略时，再考虑 Agent：

- Step 1：判断页面类型
- Step 2：决定切块方式
- Step 3：筛选重点块
- Step 4：调用 OCR 或规则工具
- Step 5：汇总最终结果

是否引入 Agent，取决于动态决策的收益是否超过额外调用、失败分支与维护成本。

## 九、工程上的几个务实建议

### 1. 保留原图

不要只保存缩略图。很多后续排查都需要回到原图。

### 2. 记录切块坐标

否则一旦模型说某块有问题，你没法回溯位置。

### 3. 汇总时保留证据来源

例如说明：

- 哪个块得出的结论
- 哪个字段来自 OCR
- 哪个判断来自模型推理

### 4. 允许“不确定”

长图场景比普通图片更容易出错，系统必须允许：

- 未识别
- 需人工确认
- 建议用户上传更清晰版本
