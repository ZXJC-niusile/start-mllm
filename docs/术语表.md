# 术语表

> 本页用于速查，不作为首次学习顺序。只有 Python 基础时，从[基础篇](./foundation/README.md)顺序学习；已经了解主要概念时，可用 [LLM 基础速通](./llm-基础速通.md)复习。涉及模型系列的词条只说明用途，具体结构与能力按版本区分。

## A

- **AnyRes**：一类处理不同尺寸与宽高比图像的策略，常结合全图和局部切图。不同模型的切图、合并与位置处理并不相同，不能仅凭名称推断实现。
- **Ablation（消融实验）**：在控制其他条件的前提下移除、替换或改变某个组成部分，观察结果变化，用于分析该部分在当前设置中的作用。单次消融不能证明普遍必要性。

## B

- **Baseline（基线）**：作为比较参照的方法，可以是简单方案、已有强方法或当前使用的系统。比较时需要说明数据、预算和评测协议。
- **BLIP-2**：早期的 Connector + 冻结 LLM 范式，用轻量 Q-Former 连接视觉与语言模型。
- **Benchmark**：包含任务、数据、划分和评分协议的评测基准。只有设置可比时，分数才适合横向比较。

## C

- **Chat Template**：把角色、消息内容和边界标记组织成模型所需序列的模板。应使用与 checkpoint 配套的配置；模板错误可能影响角色识别、生成起点和回答质量。
- **Chameleon**：Meta 提出的原生多模态模型，将图像和文本统一为离散 token 序列处理。
- **CLIP**：OpenAI 提出的图文对比学习模型，核心贡献是证明“大规模图文对 + 对比学习”可以学到强大的跨模态表示。
- **Connector / Projector**：连接视觉编码器和 LLM 的桥接层，把视觉特征映射到语言模型可消费的表示空间。
- **Cross-Attention**：一种注意力机制，让一类 token（如文本）去“看”另一类 token（如图像特征），常用于 Connector 设计。

## D

- **DPO（Direct Preference Optimization）**：利用偏好回答对优化策略模型的一种方法，不需要另行拟合显式奖励模型；标准形式还使用参考策略。它可用于偏好对齐，不能保证自动消除幻觉。
- **Dynamic Resolution**：根据图像尺寸和像素预算等条件调整视觉输入的处理方式。实现仍可能包含缩放、补边或切块；动态不等于保留全部原始像素。

## F

- **FlashAttention**：通过分块和减少显存读写实现注意力计算的方法。收益取决于硬件、形状与实现，不改变注意力要表达的基本计算目标。
- **Fuyu**：Adept 提出的原生多模态模型，直接将图像 patch 作为 token 输入，无需独立视觉编码器。

## G

- **Gradio**：一个 Python 库，可以快速搭建可交互的 Web Demo，本教程第八章使用。
- **Grounding**：让模型的回答与图像中的具体区域建立对应关系，例如“左上角的红色按钮”。

## H

- **Hallucination（幻觉）**：输出包含缺乏输入证据支持或与证据矛盾的内容，例如把图中不存在的物体说成存在。不能仅凭输出错误推断模型内部完全没有利用图像。
- **HallusionBench**：专门评测 VLM 幻觉问题（抗幻觉能力）的 benchmark，测试模型对图文矛盾的识别能力。

## I

- **Instruction Tuning / SFT**：指令微调是使用指令与回答等监督数据进行 SFT 的一种形式，帮助模型适应指令任务。SFT 的范围更广，不限于指令数据；微调也不保证每次遵循指令或回答正确。

## K

- **KTO**：使用单条输出的可取/不可取标签进行偏好优化的方法。与要求成对比较的目标相比，数据组织形式不同；标签质量与任务适配仍需检查。
- **KV Cache**：推理时缓存已计算好的 Key/Value 向量，避免重复计算，是长序列生成的核心优化。详见 [LLM 基础速通](./llm-基础速通.md) 3.1 节。

## L

- **LLaVA**：连接视觉编码器与语言模型的视觉指令学习系列。初版采用线性投影，LLaVA-1.5 改用两层 MLP；版本差异见[第三章](./chapter3/第三章%20多模态生成架构.md)及 [LLaVA-1.5 论文](https://arxiv.org/abs/2310.03744)。
- **LLaVA-NeXT / OneVision**：LLaVA 系列的后续工作，涉及高分辨率、多图或视频等能力。具体输入支持与效果需要按版本和 checkpoint 核对。
- **LMDeploy**：提供模型部署与推理服务的开源工具。模型支持、后端和硬件要求应查所用版本的官方文档。
- **LoRA**：低秩适配：通常冻结基座权重，在选定变换旁训练低秩更新分支，减少可训练参数及相关梯度和优化器状态。总显存仍包含基座、激活等成本。
- **QLoRA**：结合量化基座和 LoRA 适配器的微调方法。原论文采用冻结的 4-bit 基座，存储精度与计算精度需区分；不能由此保证任意 VLM 都能在某张显卡上运行。见[原论文](https://arxiv.org/abs/2305.14314)。

## M

- **M-RoPE（Multi-modal Rotary Position Embedding）**：Qwen2-VL 引入的多模态位置编码，统一处理文本、图像、视频的位置信息，后续版本继续发展。见 [Qwen2-VL 官方介绍](https://qwenlm.github.io/blog/qwen2-vl/#model-architecture)。
- **MiniCPM-V**：视觉语言模型系列，各版本的规模、结构与能力不同。第三章以 MiniCPM-V 2.6 为例，该版本全模型约 8B；不宜用某一早期版本的规模概括整个系列。
- **MMMU / MMMU-Pro**：多学科多模态推理 benchmark，题目难度接近大学水平。
- **MM-Vet**：开放式 VLM 评测，侧重综合任务能力。原论文使用 GPT-4（0613）文本裁判，依据问题、参考答案与模型回答评分；GPT-4V 是被测模型之一。见 [原论文第 3.2、4.4 节](https://arxiv.org/html/2308.02490v3)。
- **MLLM（Multimodal Large Language Model）**：以大语言模型为核心处理多种模态的模型。具体输入和输出模态取决于模型，不能由名称推断都支持图像、音频和视频。
- **MoE（Mixture of Experts）**：混合专家架构：路由机制为输入选择部分专家执行计算。稀疏激活可减少相对全部专家都参与时的计算，但总参数存储与通信成本仍需考虑。

## N

- **Naive Dynamic Resolution**：Qwen-VL 系列相关文献中的动态视觉输入处理概念，随尺寸与像素预算调整视觉网格；不是只由宽高比决定 patch 数量。具体规则以模型 processor 为准。

## O

- **OCR（Optical Character Recognition）**：光学字符识别，把图片中的文字提取为机器可读文本。
- **OCRBench**：专门评测 VLM OCR 和文档理解能力的 benchmark。
- **OpenAI Compatible API**：采用部分 OpenAI API 请求与响应约定的接口。兼容范围因服务而异，图像、工具调用和结构化输出等能力需要分别确认。

## P

- **Patch**：图像被切分成的小块，是 ViT 和多数视觉编码器的基本处理单元。
- **Patch Token**：图像块经过嵌入或编码后的向量位置。是否压缩、保留特殊位置以及怎样进入 LLM，由视觉编码器和连接器共同决定。
- **Pixel-shuffle**：通用 PixelShuffle 常用于上采样；InternVL 中名为 `pixel_shuffle` 的操作在 `scale_factor=0.5` 时做下采样重排：空间高宽各减半、通道数乘 4，视觉 token 数减至四分之一。见 [InternVL 实现](https://huggingface.co/OpenGVLab/InternVL2_5-8B/blob/main/modeling_internvl_chat.py)。
- **POPE**：幻觉评测 benchmark，通过针对特定对象提问 yes/no 来测试模型是否编造信息。
- **Projector**：见 Connector。
- **Prompt**：给模型的输入指令文本，多模态场景下通常包含 text + image 的组合。

## Q

- **Qwen2.5-VL**：阿里通义千问的视觉语言模型系列，支持图文理解、文档 OCR、视频分析等。
- **Qwen2.5-Omni**：可接收文本、图像、音频和视频信息，并生成文本与语音的模型；不能据此推断它也生成图像或视频。见[技术报告](https://arxiv.org/abs/2503.20215)。

## R

- **Rank（LoRA rank）**：LoRA 分支的配置宽度 r；若更新写成 BA，其矩阵秩至多为 r。r 控制适配参数规模，但实际秩不一定恰好等于 r。
- **Resolution**：图像的空间尺寸。它影响细节和成本；最终视觉 token 数还受缩放、切块、合并及重采样策略影响。
- **RLHF-V / RLAIF-V**：利用人类或 AI 反馈改善视觉语言模型行为的具体方法。RLHF-V 使用片段级人工修正与 dense DPO；不要把反馈来源直接等同于某一种强化学习算法。见 [RLHF-V](https://arxiv.org/abs/2312.00849) 与 [RLAIF-V](https://arxiv.org/abs/2405.17220)。
- **RLAIF**：利用 AI 提供的反馈进行模型对齐的一类思路。反馈生成与策略优化是不同环节，需进一步说明采用的优化目标。

## S

- **SFT（Supervised Fine-Tuning）**：有监督微调，用标注好的输入-输出对训练模型，是多模态训练的核心阶段之一。
- **SGLang**：包含模型推理与服务能力的开源系统，RadixAttention 用于复用共享前缀的 KV 缓存；效果依赖实际负载和实现。
- **System Prompt**：系统级提示，定义模型的全局行为风格，如“你是一个乐于助人的助手”。

## T

- **Target Modules（LoRA）**：指定插入低秩适配器的权重模块，如 `q_proj`、`v_proj` 或 MLP 线性层，不是逐个注意力头的开关。见 [PEFT LoRA 参数文档](https://huggingface.co/docs/peft/en/package_reference/lora)。
- **Tile**：针对高分辨率图像的宏观切块策略，先把大图切成若干子图（Tile），再对每个 Tile 分别进行 Patch 切块编码，以保留局部高清细节。
- **Token**：模型序列中的一个表示单位。文本 token 可对应子词、字节或特殊标记；视觉 token 可来自 patch 特征、合并或重采样，不一定与原图块一一对应。
- **Transformer**：基于自注意力机制的神经网络架构，是当前 LLM 和视觉编码器的基础。

## V

- **ViT（Vision Transformer）**：把 Transformer 直接应用于图像，通过 patchify 将图像转为 token 序列处理。
- **VLFeedback**：用于视觉语言偏好对齐的 AI 反馈数据集，使用 GPT-4V 评估多模态回答并生成偏好标注。见 [作者数据卡](https://huggingface.co/datasets/MMInstruction/VLFeedback)。
- **VLM（Vision Language Model）**：视觉语言模型，特指处理图文的多模态模型。
- **VQA（Visual Question Answering）**：视觉问答，给定图像和问题，模型输出答案。
- **vLLM**：提供模型推理与服务能力的开源系统，PagedAttention 用于管理 KV 缓存。多模态模型支持与运行参数应查具体软件版本。

## 其他关键缩写

| 缩写 | 全称 | 说明 |
|---|---|---|
| API | Application Programming Interface | 应用程序接口，这里指模型服务商提供的调用接口 |
| Base64 | — | 一种二进制到文本的编码方式，常用于把图片嵌入 JSON 请求 |
| CUDA | Compute Unified Device Architecture | NVIDIA GPU 并行计算平台 |
| JSONL | JSON Lines | 每行一个 JSON 对象的文本格式，本教程训练/评测数据的默认格式 |
| MLP | Multi-Layer Perceptron | 多层感知机，一种前馈神经网络 |
